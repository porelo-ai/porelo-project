# ST370 — Stories and issues kept in GitHub Issues

**Priority:** 🔼 High · **State:** Idea

**What a user gains.** A person plans in GitHub Issues instead of Markdown files in every repository: the board loads in about a second however many repositories the project has, and analysing, estimating or moving an issue needs no fetch, commit and push. A task still hands its result in to the planner, which writes it to GitHub with the person's own access; no task holds a GitHub token.

**The test.** In a test organization the planner shows the board from GitHub Issues: a story with sub-issues across repositories, state, priority and size as project fields. Moving and estimating an issue shows on GitHub at once, without a commit. A finished task's result appears on its issue under the person's name. A project carried over from its Markdown files keeps each old id.
